# KalCode 0.1.1 (preview) — release notes

The first public preview of the KalCode desktop app for Windows. It replaces 0.1.0, which was
withdrawn before public availability after an independent security review
(`docs/releases/0.1.0.md`, `docs/campaigns/SEC-0.1.1.md`). Pipeline: `docs/RELEASING.md`.

## What's in this build

- **Code:** open project folders as workspaces and run real terminals (PowerShell, Command
  Prompt, Git Bash) with tabs that come back after a restart.
- **Threads:** run Claude Code on your own Claude sign-in inside a workspace, with live status,
  streaming output, pause / stop / resume and automatic names. Codex and Gemini CLI are detected
  on the Providers page; running threads with them is not available yet.
- **Dashboard:** what is working, what needs you, what failed, and running terminals, updated live
  from KalCode's event log, filling the whole window.
- **Permissions:** the KalCode permission engine (Plan, Approve, Auto, Bypass, Custom) evaluates
  every action, keeps writes inside the workspace unless you approve, and records an audit trail.
  Claude Code threads currently refuse risky actions themselves instead of asking in KalCode; the
  in-app approval hand-off for Claude Code comes with provider panes.
- **Providers:** detection, version and sign-in state for Claude Code, Codex and Gemini CLI, read
  only. Bring your own provider: KalCode never pays for, resells or meters your AI usage.
- Features still in development (KalVoice, Agents, Missions, Automations and more) are hidden in
  this build.

## Security fixes in 0.1.1

- **Workspace-planted programs can no longer run when a thread starts** (Windows, npm-installed
  Claude Code). Provider processes never search the current folder for programs, use absolute
  `PATH` entries only, prefer the native `claude.exe`, and launch npm shims' targets directly.
- **KalCode-owned deny rules for Claude Code threads** in every mode: pushes, package publishes,
  container pushes, GitHub CLI, deploy and cloud CLIs, `ssh`/`scp`/`sftp`, and reading common
  credential files are blocked; Plan/Approve/Auto/Custom also remove file edits and web tools
  (nothing can answer KalCode approvals for Claude Code yet). The documentation now states exactly
  what KalCode enforces for Claude Code threads today and what arrives with provider panes.
- Terminals: a missing shell or a malformed `PATHEXT` is a clean error instead of a crash; shell
  detection ignores relative `PATH` entries.
- A drive root or your home folder can no longer be opened as a workspace.
- Test-only commands are absent from release builds; stricter capability and environment checks.

## Verification

- **Source gate on `7b0222a`'s tree:** `pnpm check` passed (format, lint, Clippy `-D warnings`,
  typecheck, all Rust and TypeScript tests including the security regression tests, branding,
  capabilities, zero-cost, release manifest); desktop UI suite 143 passed; real-app end-to-end
  suite 9 passed (including the v1 → v4 upgrade with backup and data preserved, and the permission
  engine inside/outside the workspace).
- **Installer:** the clean-machine install/uninstall test was not run for this build — the build
  machine has a real KalCode install, and the test must never run next to one. This exact
  installer was verified by an in-place upgrade of that install from 0.1.0: silent install exit 0,
  product version 0.1.1, the desktop shortcut launched the new build (0.1.1, beta), data and
  history intact. The full clean install/uninstall test (41 checks) passed on an earlier candidate
  with the same installer configuration.

## Windows SmartScreen

The installer is not code-signed. When you run it, Windows SmartScreen may show "Windows
protected your PC" because the publisher is unknown and the file is new. If you downloaded it from
kalcoded.com and the SHA-256 matches the value above, choose **More info → Run anyway**.

## Known limitations

- Unsigned installer and app. No in-app updates yet: install a newer version over the old one;
  settings and history in `%APPDATA%\com.kalcode.desktop` are kept.
- Threads run with Claude Code only; Codex and Gemini CLI adapters are not available yet.
- KalCode's per-action permission engine, Custom rules and approval prompts do not yet apply to
  Claude Code tool calls (see "What KalCode enforces for Claude Code threads today" in
  `docs/PROVIDERS.md`).
- Windows x64 only.
