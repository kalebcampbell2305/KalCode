# KalCode 0.1.6

This release fixes in-app updates and includes desktop sign-in and session-restoration repairs, provider-session reliability improvements, provider account switching, and KalVoice with on-device speech recognition, local command interpretation, automatic setup and voice control of threads. It is KalCode's first Stable release. The previous public build was the 0.1.1 preview for Windows.

## Upgrading

- **0.1.5 was never released.** Version numbers 0.1.4 and 0.1.5 were used only for private test builds.
- **From 0.1.4 or a 0.1.5 test build:** download the 0.1.6 installer (Windows) or DMG (macOS) from kalcoded.com/download and install it over your current copy. Those builds can't update themselves: if one offers an in-app update (0.1.4 offers "Restart and install 0.1.5"; a 0.1.5 test build may offer 0.1.6), don't accept it, because it can get stuck on "Closing your workspace" until you quit KalCode.
- **From 0.1.6 on:** KalCode 0.1.6 installs later updates from inside the app.

## Changes

- **In-app updates:** Restart to update and Restore previous version now complete. In the 0.1.4 and 0.1.5 test builds both stopped with "update_shutdown_failed" and stayed on the old version, showing "Closing your workspace" until KalCode was quit.
- **Update ready notice:** a downloaded, verified update shows Restart to update, Later and Details. Restart to update asks for confirmation, closes threads, terminals and KalVoice, and installs through the same verified path as Settings > Updates. KalCode re-checks the signed update feed about every six hours while open.
- **Desktop sign-in:** Google and Microsoft sign-in use the provider's account chooser and return to KalCode automatically, with state, PKCE, nonce and replay checks.
- **Session restoration:** startup waits for restored account authority before entering the workspace. A failure offers an accessible retry, and logout prevents late results from restoring the signed-out account.
- **Providers and workspaces:** Claude Code and Codex use your own authorized provider accounts, with repairs to provider process cleanup and interrupted-session handling.
- **Provider CLI versions:** managed sign-in and threads accept certified release lines: Claude Code 2.1.282 and later 2.1 releases, and Codex 0.155.1 through the 0.158 line. Other versions are refused with a message naming the supported versions.
- **Gemini CLI unavailable:** on June 18, 2026, Google ended Gemini CLI access through Sign in with Google for personal Google accounts (Gemini Code Assist for individuals, Google AI Pro and Ultra). Such an account can still finish sign-in in KalCode 0.1.6 and show as signed in, but its threads fail. KalCode 0.1.6 also can't set the Google Cloud project that Gemini Code Assist Standard and Enterprise licenses need, so Gemini CLI is currently unavailable in KalCode. Claude Code and Codex are unaffected. Updates will say when Gemini CLI can be used in KalCode again.
- **Provider setup guidance:** Setup and Health point provider sign-in to the account card in Providers. Each account runs in its own managed profile, so signing a CLI in from a separate terminal does not sign in KalCode threads.
- **Switch Accounts:** a thread's header shows its provider account. Moving a thread to another signed-in account, from the header, the command palette ("use codex work") or KalVoice, asks for confirmation. Past conversation stays unchanged; future messages use the new account in a new provider session. A thread never changes account on its own.
- **Account defaults:** New thread can remember each provider's account per workspace. Providers > Accounts shows each account's active threads and default workspaces, offers Set default, and "Connect another account" starts a new sign-in.
- **Crash recovery:** abandoned workspace ownership is recovered automatically when cleanup is safely verified; unresolved cleanup gives a specific reason and a safe retry.
- **Windows installation:** install and uninstall handle Windows short-path aliases consistently, including removal of KalCode's own shortcuts.
- **KalVoice:** Stable includes the KalVoice page, widget and Settings controls. KalCode sets up the on-device Whisper speech engine and local command interpretation itself from signed, checksum-verified components; no Python, Ollama or other runtime is needed. Dictation and interpretation run on your computer, and there is no connected-provider or paid-provider fallback.
- **Automatic KalVoice setup:** on first launch KalCode downloads its default English speech model, then its on-device interpreter (about 850 MB) with Pause and automatic retries; turn off "Prepare local intelligence automatically" in Settings > KalVoice to download it yourself. Downloads wait for system resources, send no audio or text, and say why a download was refused or failed.
- **Push to talk:** the key (F8 by default, configurable) works whenever KalCode is the active window. An activity bar shows listening, processing, the result, or why push to talk is not ready. A blocked microphone is reported, with Open privacy settings.
- **KalVoice after restart or reinstall:** local interpretation starts again after KalCode is reopened, and component setup works after a reinstall, even one that deleted KalCode's app data.
- **Voice to the focused thread:** holding the key in a thread's message box shows which provider, thread and account KalVoice will write to. "Send that" uses the thread's own Send; "Clear that" removes only text KalVoice typed, never yours. Terminals receive dictation without Enter.
- **Ask or tell a thread:** "Tell Authentication to run the tests" opens that thread and sends the rest through its Send. When several threads match, KalVoice asks "Which one?" and sends nothing until you choose. Voice never resumes a stopped thread or sends to one waiting for permission.
- **OWNER KalVoice:** signed usage receipts persist separately from the account session; Free and paid request accounting keeps its durable safeguards across restart.
- **Provider CLIs on macOS:** Gemini CLI and Codex installed with npm start when KalCode is opened from Finder or the Dock, using the Node.js beside them, npm's user folder, Volta or nvm's default.
- **Log redaction:** also removes more OAuth token formats, OAuth codes and state values in URLs, and KalCode session tokens.
- **Stable interface:** Stable hides entry points for features not in this build, and Providers no longer mentions API-key sign-in.

## Known issues

- Settings > Permissions says every mode is available on every plan. Stable 0.1.6 offers Plan, Approve and Auto on every plan; Bypass and Custom are planned.
- The app binaries contain file paths from the build machine, including the build account's user folder name. They contain no credentials, tokens or email addresses.
- If you start an update or Restore previous version while a provider sign-in or a file or folder picker is still open, KalCode can stop at "Closing your workspace" without updating. Close the sign-in or picker, quit KalCode, reopen it and update again.
- Don't click Restore previous version while an update is installing.
- Signing out while an update is starting may not take effect; sign out again after the update.
- On macOS, quitting while an update is being prepared can leave a hidden temporary copy and disk image until you restart the Mac; it doesn't affect your data.
- If KalVoice stays listening after you let go of the orb, press Esc.

## Platforms

| Platform | Package and requirements |
| --- | --- |
| Windows 10 (1809) or later, x64 | Signed per-user NSIS installer. |
| macOS 14 or later, Apple silicon arm64 | Developer ID-signed and notarized DMG with a stapled notarization ticket. Use `~/Applications/KalCode.app` for standard-user in-app updates and rollback. The DMG's Applications shortcut targets system `/Applications`, where later replacement requires administrator authority. |
| Intel Mac, universal Mac, Linux | No release artifact. |

Provider usage remains billed by your provider. Paid checkout is not announced in this release.
