# KalCode 0.1.5

This release includes desktop sign-in and session-restoration repairs, provider-session reliability improvements, provider account switching, and KalVoice with on-device speech recognition, local command interpretation, automatic setup and voice control of threads.

## Changes

- **Desktop sign-in:** Google and Microsoft sign-in use the provider's account chooser and return automatically to KalCode. Provider authorization codes are accepted while retaining state, PKCE, nonce and replay checks.
- **Session restoration:** startup waits for restored account authority before entering the workspace. A restoration failure offers an accessible retry, and logout prevents late restoration results from restoring the signed-out account.
- **Providers and workspaces:** Claude Code and Codex integrations use your own authorized provider accounts. This release includes repairs to provider process cleanup and interrupted-session handling.
- **Gemini CLI unavailable:** on June 18, 2026, Google ended Gemini CLI access through Sign in with Google for personal Google accounts (Gemini Code Assist for individuals, Google AI Pro and Ultra). Such an account can still finish sign-in in KalCode 0.1.5 and show as signed in, but its threads fail. KalCode 0.1.5 also can't set the Google Cloud project that Gemini Code Assist Standard and Enterprise licenses need, so Gemini CLI is currently unavailable in KalCode. Claude Code and Codex are unaffected. Updates will say when Gemini CLI can be used in KalCode again.
- **Provider setup guidance:** Setup and Health point Claude Code, Codex and Gemini CLI sign-in to the account card in Providers. Each account runs in its own managed profile, so signing a CLI in from a separate terminal does not sign in KalCode threads.
- **Crash recovery:** abandoned workspace ownership is recovered automatically when cleanup is safely verified. A running instance retains its workspace protection; unresolved cleanup provides a specific reason and safe retry.
- **Windows installation:** installation and uninstall handle Windows short-path aliases consistently, including removal of the application's own shortcuts.
- **KalVoice setup:** Stable exposes the KalVoice page, widget and Settings controls. KalCode sets up speech recognition and local command interpretation itself by downloading signed, checksum-verified local components. No separate Python, Ollama or other runtime installation is required.
- **Local KalVoice:** the production build includes the on-device Whisper speech engine. Dictation and command interpretation run on your computer. Requests that need local interpretation fail closed while it is not ready; there is no connected-provider or paid-provider fallback.
- **Component downloads:** a download refused for memory or disk capacity explains why, other download failures keep a specific safe reason, stalled transfers are bounded without cutting off healthy downloads, and an interpreter that is not installed is shown as not ready. On macOS, KalVoice's component storage is created with owner-only permissions.
- **Push to talk:** the push-to-talk key (F8 by default, configurable in Settings) works whenever KalCode is the active window and other apps keep the key the rest of the time. A press no longer opens the microphone before KalCode can show and act on it. An activity bar shows listening, processing, the result, or the exact reason push to talk is not ready; KalVoice shows Ready only when the key is registered and the speech model is active. A microphone that does not start no longer holds up the key, a Windows microphone privacy setting that blocks KalCode is reported as such, and reloading the window while the key is held ends that session instead of leaving the microphone open.
- **KalVoice after restart:** local command interpretation starts automatically after KalCode is quit and reopened, without pressing Retry, and the resource readings it waits for are available sooner after launch. If a start cannot complete, KalVoice shows the reason with Retry.
- **KalVoice after reinstall:** KalVoice component setup works after reinstalling KalCode, including when the uninstall deleted KalCode's app data. KalCode keeps the rollback protection it already recorded for signed component catalogs instead of treating it as damaged.
- **OWNER KalVoice:** signed usage receipts persist separately from the account session within Windows secure-storage limits. Verified OWNER usage remains Unlimited if the optional receipt cache cannot be written; Free and paid request accounting retains its durable safeguards across restart.
- **Provider CLI versions:** managed sign-in and threads accept certified release lines instead of one exact version: Claude Code 2.1.282 and later 2.1 releases and Codex 0.155.1 through the 0.158 line. Other versions are refused with a message naming the supported versions. Other Claude Code sign-in failures report a specific reason.
- **Switch Accounts:** a thread's header shows its provider account and lists that provider's accounts. Moving a thread to another signed-in account, from the header, the command palette ("use codex work") or KalVoice ("Switch this Codex thread to Codex Work"), asks for confirmation. Past conversation stays unchanged; future messages use the new account in a new provider session. A thread never changes account on its own, including when the default changes.
- **Account defaults:** New thread can remember each provider's account for the current workspace. Providers > Accounts shows each account's active threads and the workspaces where it is the default, offers Set default, and "Connect another account" adds an account and starts its sign-in. Gemini CLI accounts show their signed-in Google email.
- **Voice to the focused thread:** holding the push-to-talk key in a thread's message box shows which provider, thread and account KalVoice will write to, and dictation goes only into that box. "Send that" uses the thread's own Send, including prompt review; "Clear that" removes only the text KalVoice typed there since the last send or clear, never text you typed; if it can't tell which text it typed, it changes nothing and says so. Neither counts as a KalVoice request. Terminals still receive dictation without Enter.
- **Ask or tell a thread:** "Tell Authentication to run the tests" or "Ask Research why the build failed" opens that thread and sends the rest of what you said through its Send. Names can include the provider and account. When several threads match, KalVoice asks "Which one?" and sends nothing until you choose, instead of acting on a partial match. It can also list threads that need permission or failed, open one ("Open the one that failed"), "Go back", and understand "it" as the thread in front of you or the one just used. Voice never resumes a stopped thread to send to it, and never sends to one waiting for permission.
- **Faster voice results:** releasing the push-to-talk key no longer waits for an in-progress preview transcription.
- **Automatic KalVoice setup:** on first launch KalCode downloads its default English speech model from its signed component catalog, verified like a manual download; downloads wait for system resources and for push to talk to be released. Removing the model stops automatic downloads of it. Once speech is ready, KalCode also downloads its on-device interpreter (about 850 MB) from the same signed catalog, with Pause and automatic retries; turn off "Prepare local intelligence automatically" in Settings > KalVoice to download it yourself instead. These downloads send no audio or text. A blocked microphone offers Open privacy settings.
- **Update ready notice:** a downloaded, verified update shows a notice with Restart to update, Later and Details. Restart to update asks for confirmation, closes threads, terminals and KalVoice, and installs through the same verified path as Settings > Updates. KalCode also re-checks the signed update feed about every six hours while open.
- **Provider CLIs on macOS:** Gemini CLI and Codex installed with npm start when KalCode is opened from Finder or the Dock instead of failing with "env: node: No such file or directory". KalCode uses the Node.js beside them and also checks npm's user folder, Volta and nvm's default version.
- **Log redaction:** also removes more OAuth token formats, OAuth codes and state values in URLs, and KalCode session tokens.
- **Stable interface:** Stable no longer shows entry points for features not in this build, including Session Locator search, and the Providers page no longer mentions API-key sign-in.

## Platforms

| Platform | Package and requirements |
| --- | --- |
| Windows 10 (1809) or later, x64 | Signed per-user NSIS installer. |
| macOS 14 or later, Apple silicon arm64 | Developer ID-signed and notarized DMG with a stapled notarization ticket. Use `~/Applications/KalCode.app` for standard-user in-app updates and rollback. The DMG's Applications shortcut targets system `/Applications`, where later replacement requires administrator authority. |
| Intel Mac, universal Mac, Linux | No release artifact. |

Provider usage remains billed by your provider. Paid checkout is not announced in this release.
