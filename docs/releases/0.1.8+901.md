# KalCode 0.1.8 (build 901)

KalCode 0.1.8 adds Operations, one place to queue, run and follow your project's work, and brings the new KalCode logo. It also fixes a Windows freeze and a crash during voice capture when memory is low, and improves terminal focus, terminal limits and KalVoice. From this version on, later builds of 0.1.8 install by themselves when you close KalCode, so the next launch runs them, and Restore previous version never goes back to a build that can't open your data.

## Upgrading

- **From 0.1.7:** KalCode offers 0.1.8 as an update. Install it from inside the app with Restart to update or Settings > Updates, or download the installer (Windows) or DMG (macOS) from kalcoded.com/download and install it over your current copy. Your workspaces, threads, settings and sign-ins are kept.
- **Windows, from 0.1.6:** KalCode 0.1.6 can't install updates on Windows. Download the installer from kalcoded.com/download and run it once over your current copy; your data is kept. Later updates then install from inside the app.
- **macOS, from 0.1.6:** update from inside the app with Restart to update or Settings > Updates.
- **Version numbers:** KalCode shows version 0.1.8. Settings > Updates and other detailed views add the build number, for example "0.1.8 build 901". Version 0.1.2 with a build number is used only for a private test build and is never offered as an update.
- **Going back to 0.1.7:** 0.1.8 adds Operations data to KalCode's database, after first making its usual backup. KalCode 0.1.7 can't open a database that a newer version has changed, so once 0.1.8 has updated your data, Settings > Updates doesn't offer Restore previous version for 0.1.7, and a restore that would reach it stops with "The previous version can't open data saved by this version, so it can't be restored. Your data has not been changed." Restore previous version still works between builds of 0.1.8 that use the same data. On macOS, if 0.1.8 doesn't finish starting right after an update that has already updated your data, KalCode keeps 0.1.8 instead of putting 0.1.7 back; open KalCode again.

## Changes

- **Operations:** a new Operations page in the sidebar follows your project's work from the queue to its result. Add agent work, builds, tests, scripts, deploys, releases, background commands and services to the queue, with dependencies and priority; KalCode asks you to confirm before anything runs, and a restart never reruns work on its own. The page has five views. Runs keeps each run's status, output log and history, and the files a command reports as its outputs. Queue lists waiting work in order and opens the run of anything that is already running. Services shows the processes and ports in your workspaces, and lets you stop or restart the services that Operations started. Environments shows Local, Preview, Staging and Production for each workspace; a deploy counts as unverified, because KalCode doesn't check the health of deployed sites. Activity shows recent run events and commits. Operations terminals count toward your plan's terminal limit.
- **Later builds install when you close KalCode:** a newer build of the version you use, such as 0.1.8 build 901 to the next build of 0.1.8, downloads and is verified in the background, then installs without a prompt when you close KalCode, so the next launch runs it. Settings > Updates says when a build will install on close. It never installs while KalCode restarts, or while Windows is signing out or shutting down. On Windows the installer runs silently; on macOS KalCode checks that the new build starts before keeping it, and otherwise keeps the build you had. If you open KalCode while a build is installing, KalCode opens the new build as soon as the install finishes. If a build can't install this way, KalCode offers it with the usual Restart to update prompt instead. A new version, such as 0.1.7 to 0.1.8, still asks first.
- **Windows no longer freezes on focus changes:** the KalCode window could stop responding and had to be ended from Task Manager when keyboard focus moved away from KalCode while it was handling key presses. This affected 0.1.6 and 0.1.7 on Windows. KalCode now includes the upstream fix for that input lock in its windowing library.
- **KalVoice no longer closes KalCode when memory is low:** if your computer ran short of memory while KalVoice was recording, KalCode could close without warning. KalVoice now stops that recording instead and says your computer is low on memory, and KalCode keeps running. This applies on Windows and macOS.
- **Terminal focus:** focusing a terminal pane, shell or provider, runs one quick blue trace around its edge and then keeps the thin blue outline. It plays once per focus and never loops; with reduced motion turned on it is skipped. Unfocused panes stay neutral.
- **Amber means waiting for you:** a thread or terminal that needs you, such as one waiting for a permission answer, is shown in amber everywhere, including the badge on its row. In the light theme the amber is a darker shade so the text stays readable.
- **Terminal limits follow your plan:** the fixed limit of 12 terminals per workspace now depends on your verified plan. Free and Pro keep 12 per workspace; MAX, MAX 2X and Owner have no KalCode limit. If your plan can't be verified, the Free limit applies. The same limit applies to terminals you open with KalVoice. Reaching the limit never closes open terminals, and the message names your plan and its limit. Restarted and restored terminals are not affected.
- **KalVoice prepares its speech model once per take:** when you start talking, KalVoice checks and prepares the selected on-device speech model once, before the microphone opens, and uses that same model for the whole take, instead of repeating the selection and checks during and after the take. If the model can't be prepared, the microphone doesn't open. If you change the model during a take, the change applies to the next take. Every new take checks readiness again.
- **KalVoice widget no longer covers pane controls:** when the widget is docked at the top or bottom and shows a lasting problem, such as speech unavailable or push to talk turned off, it stays in its own band instead of covering the controls of the pane below it.
- **New KalCode logo:** the KalCode mascot is now the app icon on Windows and macOS and the logo inside the app.
- **Secret redaction:** redacting text a second time no longer marks the leftover part of an already redacted value as a new secret, so redacted text stays the same.
- **Restore previous version protects your data:** KalCode records the build that last updated its database, before the update runs, and offers or performs Restore previous version only for a build at or after that one. A build that doesn't finish starting is no longer counted as a successful update.
- **Builds within a version:** KalCode can update to a newer build of the same version, so improvements reach you as soon as they're ready. macOS installs an update only when the downloaded app's build number matches the update exactly.

## Known issues

- Settings > Permissions says every mode is available on every plan. Stable 0.1.8 offers Plan, Approve and Auto on every plan; Bypass and Custom are planned.
- The app binaries contain file paths from the build machine, including the build account's user folder name. They contain no credentials, tokens or email addresses.
- Gemini CLI is still unavailable in KalCode, as described in the 0.1.6 notes. Claude Code and Codex are unaffected.
- If you start an update or Restore previous version while a provider sign-in or a file or folder picker is still open, the update stops and KalCode says to close sign-in or file dialogs and try again.

## Platforms

| Platform | Package and requirements |
| --- | --- |
| Windows 10 (1809) or later, x64 | Signed per-user NSIS installer. |
| macOS 14 or later, Apple silicon arm64 | Developer ID-signed and notarized DMG with a stapled notarization ticket. Use `~/Applications/KalCode.app` for standard-user in-app updates and rollback. The DMG's Applications shortcut targets system `/Applications`, where later replacement requires administrator authority. |
| Intel Mac, universal Mac, Linux | No release artifact. |

Provider usage remains billed by your provider.
