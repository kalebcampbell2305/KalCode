# KalCode 0.1.9 (build 1980)

Source commit: `dbc5ee2327e40afd14a6ccfc2f798a63b141f8d9`.

## New in this build

- **Option+Arrow moves by word again on macOS.** Option+Left and Option+Right were taken as Back and Forward everywhere in KalCode, so in terminals, Claude and Codex panes and text fields they changed the page instead of moving the cursor by a word. On macOS they now move by word; Back and Forward stay on Command+[ and Command+], as the tooltips show.
- **Stuck handoffs end with a reason.** A queued handoff that hit an error that can't be retried could stay queued forever, retrying with nothing shown. It now stops with a short explanation. The Hand off dialog lists every handoff still in progress plus the 8 newest finished ones, so an older queued handoff keeps its Cancel and Report actions, and a send that fails no longer hides a handoff it had already created. Screen readers now hear which agent each row action is for.
- **Threads keep their place.** An archived thread you have open stays read-only with Unarchive offered, even after it leaves the list. Long threads have "Load earlier messages" at the top, which keeps your scroll position. Reading new messages now clears the unread badge.
- **Unified Memory refreshes quietly.** Background refreshes no longer clear an error you are reading, flash "Searching" or disable the buttons. Typing a search and pressing Refresh work as before.
- **The top bar never draws text over text.** In narrow windows the context chips no longer slide under the command field, and at Larger text the "Ctrl K" hint hides when the field is too narrow instead of covering the working count.
- **Small visual fixes.** The KalVoice widget's status, such as "Waiting for system resources", is no longer cut off. Usage details in Providers > Accounts wrap to a second line instead of stopping mid-sentence. The New agent dialog keeps a place for providers that are still being detected, so it no longer jumps when Codex or Gemini CLI appear. The commas in the Activity empty state line up with the text.
- **KalVoice retry waits read in hours.** A long retry wait now says "about an hour" instead of "about 60 minutes".

## Platforms

- Windows 10 version 1809 or later, x64.
- macOS 14 or later, Apple silicon.
