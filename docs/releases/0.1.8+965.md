# KalCode 0.1.8 (build 965)

This build of KalCode 0.1.8 adds the Command Deck, gives KalVoice natural control of the work already visible in KalCode, adds KalTidy, adds an Account Hub at the foot of the sidebar, and redesigns Providers > Accounts. It keeps your workspaces, threads, settings and sign-ins, while adding saved model-effort data that older builds cannot open safely.

## Upgrading

- **From an earlier build of 0.1.8:** this build downloads and is verified in the background, then installs without a prompt when you close KalCode, so the next launch runs it. Your workspaces, threads, settings and sign-ins are kept. You can also download the installer (Windows) or DMG (macOS) from kalcoded.com/download and install it over your current copy.
- **From 0.1.7:** KalCode offers 0.1.8 as an update. Install it from inside the app with Restart to update or Settings > Updates, or download the installer (Windows) or DMG (macOS) from kalcoded.com/download and install it over your current copy. Your workspaces, threads, settings and sign-ins are kept.
- **Windows, from 0.1.6:** KalCode 0.1.6 can't install updates on Windows. Download the installer from kalcoded.com/download and run it once over your current copy; your data is kept. Later updates then install from inside the app.
- **macOS, from 0.1.6:** update from inside the app with Restart to update or Settings > Updates.
- **Version numbers:** KalCode shows version 0.1.8. Settings > Updates and other detailed views add the build number, for example "0.1.8 build 965". Version 0.1.2 with a build number is used only for a private test build and is never offered as an update.
- **Going back to an earlier build:** this build adds saved model-effort data to KalCode's database, after first making its usual backup. Builds 923, 901 and 0.1.7 predate that data, so once this build has updated your data, Settings > Updates doesn't offer Restore previous version for them. A restore that would reach an older database format stops without changing your data. On macOS, if this build doesn't finish starting after updating your data, KalCode keeps the newer app instead of putting an incompatible older build over it; open KalCode again.

## Changes in this build

- **Command Deck keeps the project in view:** the new main shell puts the active workspace, Git branch, environment, permission mode and command palette in the top bar. A Projects rail keeps workspaces close, the Agents rail groups work that needs you, is working, is blocked or just finished, and the bottom strip reports builds, tests, provider health and what is shipping from KalCode's live state. Missing data stays visibly unavailable instead of being guessed.
- **KalTidy stops idle terminals:** the broom button in the Code toolbar stops every idle terminal in one click, and Review terminals lists each terminal with the reason it is idle, waiting, background or protected before you choose. A terminal is idle when its shell is at the prompt with nothing running, no unsent typing, no output for at least 2 minutes and no focus, or when its shell has already exited. Terminals running Claude Code, Codex or an unfinished Operations run, the focused terminal, and terminals hosting a service or listening port are never stopped by default. If KalCode can't check a terminal's processes, nothing is stopped. Also in the Command Palette, and in KalVoice: say "close all idle terminals", "tidy up terminals" or "which terminals are idle".
- **Account Hub:** your name, initials and plan now sit at the bottom of the sidebar. Click it for Account & plan, Usage, Billing, Connected providers, KalVoice, Preferences, Appearance, Keyboard shortcuts, Settings and Sign out. The build number moved from the sidebar footer into this menu.
- **Providers > Accounts redesign:** accounts are a compact list grouped by provider, with a filter once you have more than 6, Add account, health and sign-in status, and quick actions for sign-in, refresh, default, rename, sign-out and remove. Details shows identity, sign-in, last use and active threads. Providers don't report per-account plans or usage, so KalCode shows "Not reported" or "Usage unavailable" instead of guessing. Accounts are named and ordered the same way in thread pickers, pane headers, the Command Palette, Operations and KalVoice.
- **KalVoice understands what is on screen:** ask it to open, focus or describe a workspace, thread, terminal, provider pane, browser, Operations run, queue item, service, environment or recent result. It resolves names against the current KalCode scene, asks when two choices are equally valid, and rechecks the chosen target before acting.
- **Talk directly to terminals and agents:** KalVoice can insert dictated text into an exact terminal or provider pane. Raw terminals remain insert-only; provider panes use their normal governed send path and refuse stale or replaced sessions, known approval prompts and providers that are waiting for you.
- **Launch and configure agent groups:** ask for one or more Claude Code, Codex or Gemini threads with a workspace, account, model, effort and assignment. KalCode checks the whole request before starting anything, asks only for ambiguous choices, and reports the exact started, queued and failed counts. Follow-ups can change the exact unused group you just launched.
- **Full Claude model IDs and provider effort:** Claude aliases and complete model IDs are validated consistently. Claude and Codex effort settings are kept with the thread across restart and resume; Gemini says when effort is unsupported instead of pretending to apply it.
- **Natural follow-ups and cancellation:** phrases such as "open it", "focus it", "the other one" and "use High effort for all of them" keep bounded context for the exact selected targets. A newer request cancels queued work from the older request, cancelled pane actions are discarded before navigation, and the history reports what actually settled.
- **Local-first names and reasoning:** KalVoice learns bounded workspace, thread, provider, account, model, branch and repository vocabulary for speech recognition without sending that vocabulary to a connected provider. Deterministic commands run first; grounded local reasoning gets only sanitized, owner-visible scene metadata and a short deadline.
- **Spoken lifecycle updates:** when enabled, KalVoice can announce a named completion, failure, permission request, sign-in request, provider disconnect, deploy or release result. It stays silent while the microphone is active and during shutdown, deduplicates repeats, and doesn't claim speech started when the OS voice backend failed.
- **Safer bulk control:** counted requests such as stopping several agents bind to the exact live sessions that were checked. Concurrent replacements are left alone, partial completion says how many actually stopped, and ambiguous pane names are refused instead of closing the wrong pane.

## Changes in KalCode 0.1.8


- **Operations:** a new Operations page follows your project's work from the queue to its result: agent work, builds, tests, scripts, deploys, releases and services, with dependencies and priority. KalCode asks before anything runs, and a restart never reruns work on its own. Runs, Queue, Services, Environments and Activity show status, logs, waiting work, processes and ports, deploy targets and recent events. Operations terminals count toward your plan's terminal limit.
- **Later builds install when you close KalCode:** a newer build of the version you use, such as 0.1.8 build 923 to build 965, downloads and is verified in the background, then installs without a prompt when you close KalCode. Settings > Updates says when a build will install on close. It never installs while KalCode restarts or Windows signs out or shuts down. On macOS KalCode checks that the new build starts before keeping it. If a build can't install this way, KalCode offers it with Restart to update. A new version, such as 0.1.7 to 0.1.8, still asks first.
- **Windows no longer freezes on focus changes:** the KalCode window could stop responding and had to be ended from Task Manager when keyboard focus moved away from KalCode while it was handling key presses. This affected 0.1.6 and 0.1.7 on Windows. KalCode now includes the upstream fix for that input lock in its windowing library.
- **KalVoice no longer closes KalCode when memory is low:** if your computer ran short of memory while KalVoice was recording, KalCode could close without warning. KalVoice now stops that recording instead and says your computer is low on memory, and KalCode keeps running. This applies on Windows and macOS.
- **Terminal focus:** focusing a terminal pane runs one quick blue trace around its edge, then keeps a thin blue outline. Reduced motion skips the trace.
- **Amber means waiting for you:** a thread or terminal that needs you, such as one waiting for a permission answer, is shown in amber everywhere, including the badge on its row. In the light theme the amber is a darker shade so the text stays readable.
- **Terminal limits follow your plan:** Free and Pro keep 12 terminals per workspace; MAX, MAX 2X and Owner have no KalCode limit; an unverified plan gets the Free limit. Reaching the limit never closes open terminals.
- **KalVoice prepares its speech model once per take,** before the microphone opens; if it can't, the microphone doesn't open.
- **KalVoice widget no longer covers pane controls** when docked at the top or bottom with a lasting problem.
- **New KalCode logo:** the KalCode mascot is now the app icon on Windows and macOS and the logo inside the app.
- **Secret redaction:** redacting text a second time no longer marks the leftover part of an already redacted value as a new secret, so redacted text stays the same.
- **Restore previous version protects your data:** KalCode records the build that last updated its database, before the update runs, and offers or performs Restore previous version only for a build at or after that one. A build that doesn't finish starting is no longer counted as a successful update.
- **Closing a terminal or agent ends it** (build 923): closing a terminal tab or pane ends its shells, and closing a Claude Code or Codex pane stops the agent. Nothing keeps running in the background. Docking or collapsing a pane doesn't close it.
- **F8 push to talk after switching back (Windows, build 923):** F8 becomes available again within about half a second of KalCode getting focus back.
- **KalCode logo on the Windows installer** (build 923).

## Known issues

- Settings > Permissions says every mode is available on every plan. Stable 0.1.8 offers Plan, Approve and Auto on every plan; Bypass and Custom are planned.
- The app binaries contain file paths from the build machine, including the build account's user folder name. They contain no credentials, tokens or email addresses.
- Gemini CLI is still unavailable in KalCode, as described in the 0.1.6 notes. Claude Code and Codex are unaffected.
- If you start an update or Restore previous version while a provider sign-in or a file or folder picker is still open, the update stops and KalCode says to close sign-in or file dialogs and try again.
- KalVoice intelligence (assistant) responses can be delayed: after you finish speaking, an answer or action can take noticeably longer than usual to arrive.
- After updating, KalVoice's on-device intelligence can take a few minutes to become ready while KalCode finishes cleaning up the previous version's worker; it then starts on its own.
- Codex and Gemini don't expose every provider-native approval prompt to KalCode. KalVoice never bypasses those prompts, but a normal voice send can arrive while an unreported prompt is visible; check the provider pane when it is waiting for you.
