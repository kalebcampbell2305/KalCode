# Campaign Z3 — Threads

Goal: persistent units of AI work. A thread runs one provider session in one workspace under one
permission mode; its status is structured runtime truth; everything it does is persisted and
recorded as events; it survives crashes and one provider's failure never affects another's
threads.

Branch `z3/threads`. Design: `docs/AGENT_RUNTIME.md`. Screenshots:
`apps/desktop/qa/screenshots/threads-*.png` (git-ignored; regenerate with
`KALCODE_UI_TEST_PORT=1434 pnpm --filter @kalcode/desktop test:ui --grep @screenshots`).

Criteria are PASS only when executed. **PENDING-INTEGRATION** marks behaviour that is built and
tested against the contract seams (fake provider, test gate, fake resolver) but cannot be proven
end to end until Z1 (workspaces), Z2 (Claude Code adapter) or Z4 (permission engine) merge.

## Design summary

- **Runtime:** new crate `crates/threads` (`kalcode_threads::ThreadRuntime`). Depends only on
  `crates/contracts` and native-core; three injected seams: `ProviderRegistry`
  (`Arc<dyn AgentProvider>`), `WorkspaceResolver` (`list`, `resolve → { id, name, root }`),
  `PermissionGate`.
- **Concurrency:** one channel + worker thread per live session (a provider's sink only
  enqueues); per-thread state behind one mutex; lock order thread state → database; the
  database lock is never held while calling a provider, gate or resolver; bus subscribers only
  enqueue; session generations make events from stopped/replaced sessions inert.
- **Atomicity:** `Core::write_with_events` (additive native-core API) commits a state change and
  its events in one transaction and publishes after commit.
- **Status:** providers may set only working states; lifecycle, approval and pause states are
  runtime-owned; a paused thread stays paused until resumed.
- **Permissions:** `ApprovalRequired` → runtime rewrites the action's identity → `evaluate` →
  Allow (approve once) / Deny / Ask (`open_request`, `waiting_for_permission`); decisions from
  `approval.*` events are forwarded to the session; failures to record an approval fail closed.
- **Live text:** `thread_stream` per-window channel with catch-up for late subscribers; persisted
  history and state changes arrive through the event log.
- **Non-UI API:** the same runtime serves the voice layer (KalVoice intents map 1:1: task-less
  `create_idle_threads`, `find`, `pause/resume/stop_threads(ThreadScope)`, `status_summary`).

## Screenshot review fixes

1. At 1024 the list truncated names because the timestamp shared their line → moved the time to
   the meta line.
2. The approval notice ran the request and the guidance together without punctuation → split
   into "Requested: …" and a guidance line.
3. Header copy wrapped to an orphan at 1024 → shortened.
4. Light theme: faint text and the waiting badge fell below 4.5:1 on the selected row / tinted
   notice (axe) → muted text on selection, opaque base under the badge, muted error code.
5. A streamed message stayed "Writing" after interrupt (the flush didn't complete it on the
   stream) → the runtime now publishes `message_completed` for flushed text (native + memory),
   with a regression test.

## Known issues / notes for the lead

- **Command palette ranking (Z0):** cmdk does not re-sort matches in this app (the query
  "threads" selected the first destination whose description mentions threads, not Threads). Thread commands are placed
  first so "new thread" / "search threads" select correctly; the underlying sort bug remains.
- `ThreadSummary` has no archived flag; the UI infers it by diffing the list with and without
  archived threads (contract request below).
- Pre-integration the shipped app has no providers and no workspaces, so no thread can be
  created there; the surface shows honest empty states.

## Contract change requests (for `crates/contracts` / docs/CONTRACTS.md)

1. **Add `thread_options` and `thread_tool_calls` to the IPC table** (Z3-owned, additive). The
   New thread flow needs the registered providers and resolvable workspaces; the detail view
   needs tool calls. Types (`ThreadOptions`, `ProviderOption`, `WorkspaceOption`,
   `ToolCallRecord`, `ToolCallStatus`) live in `kalcode_threads::types` today; move them into
   contracts if Z5 or the voice layer consume them over IPC.
2. **`ThreadSummary.archivedAt: Option<String>`** — surfaces can't tell archived threads apart
   in `thread_list { includeArchived: true }`.
3. **`ThreadSummary.resumable: bool`** (optional) — whether resume restores the provider's
   conversation or starts fresh, so the UI can say so before the user resumes.
4. **`thread_create` and Bypass/Custom:** the contract lists `permissionMode` without
   `confirmBypass`; the runtime refuses Bypass and Custom at creation (set later through
   `thread_set_permission_mode`, Z4). Confirm, or add `confirmBypass`/`profileId` to
   `thread_create`.
5. **`thread_send` / `thread_interrupt` / `thread_stop` input** is listed as `{ threadId, text? }`
   for all four; implemented as `thread_send { threadId, text }` (required),
   `thread_resume { threadId, text? }`, `thread_interrupt/thread_stop { threadId }`. Z5's
   Dashboard calls match. Retry on a failed thread is `thread_resume` (no `thread_retry` needed).
6. **EVENT_PROTOCOL.md catalog:** Z3 thread/agent/tool/file events are now emitted (status I);
   thread events also carry `correlation.workspaceId/providerId`.
