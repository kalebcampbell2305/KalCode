# Campaign Z7-W4 — Provider panes and the hook bridge

Writer W4 of campaign Z7 (`docs/campaigns/ADVANCED.md` §16). Branch `z7/provider-panes`, worktree
`.worktrees/z7-panes-provider`, from main `87d9316`, with main `65fe095` (classifier hardening,
SEC-LATENT) merged in. Threat model first: `docs/campaigns/Z7-W4-THREATS.md` (commit `080ac25`,
before any code). Design and as-built description: `docs/PROVIDER_PANES.md`.

No provider session was started and no AI quota was used. Every test runs the fake provider
(`kalcode-fake-provider`, interactive mode) in a real PTY behind the real hook helper and bridge.
The real-CLI smoke run is written (`tooling/smoke/claude-interactive-smoke.ps1`) and awaits the
owner's approval.

Delivered:

- **`crates/hook-bridge`** (new): the `kalcode-hook` helper and the bridge server. Per-run random
  named pipe (`FILE_FLAG_FIRST_PIPE_INSTANCE`, remote clients rejected) or a private Unix socket;
  mutual HMAC-SHA256 challenge under a per-session key that never crosses the wire; filtered,
  bounded hook records; `PreToolUse` fails closed, status events fail open. No new `unsafe`; no new
  crates (hmac, sha2, getrandom, hex, tokio were already in the lockfile).
- **`crates/pty`**: `PtySession::spawn_program(ProgramSpec)`, the Z1 launch API for provider CLIs
  (argv, cleared environment). Additive.
- **`crates/providers/src/interactive`**: Claude Code interactive argv, deny floor and settings
  file; `InteractiveSession` (hook → `AgentEvent`, held approvals); `InteractiveClaudeProvider`;
  `RuntimeRouter` (interactive vs headless per thread until `threads.runtime_kind`); `PaneRegistry`;
  Codex read-only-first argv and OSC 9 scanner (not wired); fake-provider interactive mode.
- **`crates/permissions`**: `PermissionService::expire_answered_in_provider`.
- **Desktop**: `provider_pane_*` IPC (`provider_pane_commands.rs`) behind the `provider_panes`
  feature flag; pane UI in `apps/desktop/src/surfaces/code/panes/**`; in-memory pane runtime for
  ui-test builds (`ipc/memory/panes.ts`).

Criteria are PASS only when executed. **PENDING** means not built or needing a lead/owner step.

## 2. Security gates (threat model §4)

| Threat | Result | Tests |
| --- | --- | --- |
| Forged calls (no key, wrong key, unknown session) | Rejected, handler never runs | `forged_request_without_the_key_is_rejected_and_blocks`, `unknown_and_revoked_sessions_are_rejected` |
| Replay / tampering | Rejected (fresh server nonce; body MACed) | `replayed_and_tampered_requests_are_rejected`, `wire::tests::*` |
| Impostor server / replayed reply | Helper fails closed | `helper_rejects_an_impostor_or_replayed_reply` |
| Pipe squatting | Bridge refuses to start; panes stay off | `a_taken_pipe_name_is_refused` (Windows) |
| Stale sessions | Revoked on exit/stop | `unknown_and_revoked_sessions_are_rejected`, `stopping_a_pane_ends_its_process_and_revokes_the_session` |
| Unreachable / slow / oversized / panic | Exit 2 before the hook timeout | §1 Z7-05; panic hook in `bin/kalcode_hook.rs` |
| Approval flood from a session | ≤ 8 held; more go to the provider prompt | `held_approvals_are_bounded` |
| Payload leakage | Tool output, transcript, assistant text dropped; prompt only for the title | `drops_fields_kalcode_does_not_need`, `status_events_are_forwarded_filtered`, `first_prompt_is_used_only_for_the_title` |
| Repository influence | `--setting-sources user` / `--restricted`, `--strict-mcp-config`, exec-form hooks, absolute helper | argv tests; settings test |
| Classifier gaps (SEC-LATENT §5) | Sent as opaque (always ask): recursive searches, pipelines, multi-level wildcards | `classifier_gaps_are_opaque` |
| WebView input | ids/enums/bounded text only; feature flag native | `provider_pane_commands.rs`; capability check |

## 6. Deviations and open items

- **Runtime kind until v12.** A `RuntimeRouter` decides per thread (marker file in
  `<data>/sessions/<thread>/`); `ThreadSummary.runtimeKind` / `terminalId` stay `null` natively.
- **Mirrored provider prompts** show WAITING FOR YOU ("Answer in Claude Code"), not PERMISSION
  REQUIRED: the Z3 runtime ignores `waiting_for_permission` from providers (lead decision).
- **No `pane.info_changed` event**: the UI refreshes on thread events and polls while a pane's
  hook channel is still `waiting`.
- **Codex / Gemini panes** not wired; `crates/continuity` not built; `-n <title>` on relaunch not
  passed (the title isn't in `SessionConfig`); Custom `never` rules not in the deny floor.
- **Owner smoke run pending** for: `--settings` hooks with `--setting-sources user`, exec-form
  `args`, hook environment inheritance, the UserPromptSubmit field name.
