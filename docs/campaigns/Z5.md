# Campaign Z5 — Dashboard

Goal: the production Dashboard — runtime truth about threads, approvals and terminals — built on a
typed data layer that consumes the shared contracts and switches to native data as Z1, Z3 and Z4
land, with no fixture data in shipped builds.

Design and API: `docs/DASHBOARD.md`. Evidence screenshots: `docs/campaigns/z5-evidence/` (full set
of 60 generated by `pnpm test:ui --grep @dashboard-shots` into `apps/desktop/qa/screenshots/dashboard/`).

The directive's §56 matrix text is not in the repository; the criteria below are the product
directive §7 Dashboard requirements as given in the Z5 brief. Criteria were marked only from
executed tests or reviewed screenshots. **PENDING-INTEGRATION** means the Dashboard side is done
and verified against the contract-faithful memory transport, and needs the owning campaign's
native command to be verified end to end.

## Visual review iterations

1. Thread rows collapsed to a stacked layout at 1440 (the main column is ~46 rem): rebuilt as
   status | detail | time-and-actions with a compact meta line; added a medium container layout.
2. Status labels truncated ("Running a comm…"): shortened labels and allowed wrapping.
3. Approval metadata truncated provider/model and misaligned values: split model and branch onto
   sub-lines, fixed column alignment, moved the mode explanation to a tooltip.
4. Hidden keyboard hints took layout space and pushed "Asked …" to the middle: hints now render
   only while the request has focus.
5. Duplicate danger signals ("Leaves this machine" plus a red scope badge): one signal kept.
6. Loading and error states showed a green "all clear" shield: neutral shield until data is known.
7. Recent outcomes repeated the Threads error and skeleton: reported once, by Threads.
8. Approval request panel collapsed too early at 1280: collapse threshold lowered.
9. Failed-thread error text in full red read as alarming: secondary text, two-line clamp; the
   status glyph carries the tone.

  `docs/CONTRACTS.md` (`{ threadId }`, `{ requestId, decision }`, `{ status }`,

  or add `thread_retry`.
- Z4: unify `ApprovalItem` with the reusable `PermissionPrompt`.
