## APIs for the other writers

- **Show content in panes (W3 Dashboard, W2 surfaces):** `registerPaneContent("dashboard", { describe, render })`
  from `apps/desktop/src/shell/panes` (`describe(content) → TabInfo { title, glyph, tone?, stateLabel?, statusText? }`,
  `render(content, { paneId, tabId, focused, focusRequest }) → ReactNode`). Call it at module load of the
  Dashboard's pane view; the canvas re-renders when a registration arrives. Widgets:
  `registerPaneWidget(widgetId, …)`; widget ids `^[a-z0-9][a-z0-9_.-]{0,63}$`. `registeredWidgets()` feeds the
  "Add" menus. Until W3 registers, the Dashboard pane shows an honest "Open Dashboard" notice.
- **Card → pane focus, notifications, search results:** `useOpenInPane()(content, { workspaceId })` switches to
  the content's workspace, goes to Code and opens and focuses it once that workspace's canvas is up. A thread that
  isn't a provider pane opens in Threads. Lower level: `dispatchPaneCommand(command, { queue, scope })`.
- **Layout store for PC/BP:** `kalcode_workspace_ui::store::{get_layout, save_layout, list_presets, save_preset}`
  (Rust) and the five `layout_*` IPC commands; the stored value is the contract `PaneLayout`.
- **Shell slots:** `useShellSlots()` (`shell/ShellSlots.tsx`) for anything that must float without covering
  headers.

## Decisions and deviations

1. **Close hides, End stops.** Z1 ended shells on tab close; Z7-14 requires that closing a pane
   never stops its process. Every close (tab ×, Delete, Ctrl+Shift+W, pane ×, Ctrl+Alt+W,
   KalVoice) hides; "End terminal" (pane menu) is the explicit stop; an exited shell's tab tidies
   away on close. `docs/CODE_MODE.md` updated; Z1's UI and E2E tests assert this with real
   processes.
2. **Built-in presets live in the UI model**, not in `layout_presets` (that table holds user
   shapes; `builtin` stays for future curated presets). Grids fill row by row.
3. **Absolute layout** instead of nested flex: panes never remount on split/move, so terminals and
   provider TUIs keep their view (only moving a tab to another pane re-attaches it).
4. **A focus request belongs to the content in front when it was made**, so arrow-key tab
   switching never pulls keyboard focus into the newly shown terminal.
5. **Reopen restores the tree**: a closed pane returns beside the same neighbouring subtree with
   the share of space it had (unit test: exact round trip; E2E: divider value).
6. **KalVoice slot band**: 6 px around the compact widget; the expanded widget still overlays
   downward while it shows a transcript (transient). Left/right/free placements float as chosen,
   never over the sidebar.
7. **W3 widget layout** stays in W3's per-viewer WebView storage; moving it into the layout store
   needs a field the contract `PaneLayout` doesn't have (lead decision).
8. The dock is `PaneLayout.dock` (contract); undocking to a separate OS window is phase 2.
