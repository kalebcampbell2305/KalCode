## Migration v11 (provisional, not registered)

`crates/notifications/migrations/0011_notifications.sql`, `kalcode_notifications::NOTIFICATIONS_MIGRATION`
(version 11). **Not** in `kalcode_core::db::MIGRATIONS` — the lead registers it at merge (a test
asserts it is isolated). Table per `CONTRACTS_ADVANCED.md` §9 v11 plus `workspace_id`, `updated_at`
(last raise; list order) and `count` (coalesced events), CHECKs on kinds/severity/entity pairs,
indexes for recency, unread and the dedupe key. Until it is registered the center detects the
missing table and keeps notifications in memory (logged as `notifications.not_persisted`); both
backends run the same policy and are tested for identical results, and persistence across restart
is tested on SQLite.

## APIs

- **Pane content (for W1):** `DashboardPane` (`surfaces/dashboard/index.ts`) for
  `PaneContent::Dashboard`; `WidgetPane({ widgetId })` + `widgetPaneMeta(id)` for
  `PaneContent::Widget`; `AVAILABLE_WIDGETS` for an "add widget" menu.
- **Focus:** `useUiIntents().focus(target)`; W1 registers `registerFocusHandler(t => …)` and
  returns `true` when it focused (or opened) the pane. `usePaneFocusRequests` is how today's
  provider panes (Code surface) answer.
- **Commands:** `notification_list { unreadOnly, limit 1..200, before }` → `NotificationPage`
  `{ notifications, nextCursor, unreadCount }`; `notification_mark { ids | null, mark:
  read|unread|dismissed }` → count. Event `notification.created { notificationId, kind, severity,
  entityKind, entityId }` (created or re-raised by coalescing).
- **Other systems** (AUT, DOC, PH, PC, HS) create notifications through `kalcode_notifications`.

## Critique against the concepts, and what is left

- The concepts' KPI tiles carry sparklines of metrics KalCode doesn't record (success rate, tokens);
  the app shows only real counts and an events-per-5-minutes trend from the event log.
- The concepts' progress bars (72 %, 41 %) are not reproduced: providers report no progress, and
  KalCode never fabricates it. Cards show the structured current activity instead.
- The KalVoice widget still overlaps page headers at the top centre (pre-existing, W1/W2 shell slot).
- View changes on DONE cards waits for a diff surface in the app (Z6a DiffView is not wired to a
  surface); Agent and Mission grouping wait for Z8/Z9.
- Widget layout is per viewer (WebView storage); moving it into the W1 layout store is a follow-up.
