# Campaign Z2 — Provider runtime

Goal: the native provider foundation (detection, capabilities, permission mapping, process
supervision) and one provider — Claude Code — working end to end through the shared
`AgentProvider` / `AgentSession` contracts, plus an honest Providers surface.

Branch `z2/provider-runtime`. Criteria are marked PASS only after being executed. No command that
sends a prompt or uses AI quota was run; real-provider session tests are `#[ignore]`d.

## Design summary

- **`crates/providers` (`kalcode_providers`)** consumes the shared contracts
  (`kalcode_contracts::agent`, `::permissions`, `::events`); Claude Code wire types stay private
  to the adapter.
  - `detect`: resolves the executable on `PATH`, then documented install folders; runs only
    `--version` (15 s timeout) and a documented status command (`claude auth status` exit code;
    `codex login status` leading phrase; none for Gemini → `unknown`).
  - `catalog`: providers, capabilities, researched permission mappings, install/sign-in commands.
  - `process`: argv-only spawn, `env_clear` + per-provider allow-list, 8 MiB line cap, 16 KiB
    redacted stderr tail, timeouts, process-tree kill (taskkill /T on Windows, process groups on
    Unix) on terminate and drop.
  - `registry`: cached detection, one thread per provider (a hang or panic affects only its own
    row), `provider.detected` / `provider.error` on change, `usable()` for provider pickers.
- **Claude Code adapter**: `claude -p --input-format stream-json --output-format stream-json
  --verbose --include-partial-messages --permission-prompts none --strict-mcp-config` plus mode
  flags; `--session-id <uuid>` / `--resume <id>`; stream parser → normalizer → `AgentEvent`;
  tool calls → `NormalizedAction`; interrupt via the documented control request only when
  `interrupt_receipt_v1` is advertised, otherwise (or unconfirmed within 5 s) the process is
  stopped (stricter, resumable); unexpected host permission requests fail closed.
- **Permission mapping**: every KalCode mode maps to an *approximate (stricter)* Claude Code
  setting; `bypassPermissions`, Claude's `auto`, `--dangerously-skip-permissions`,
  `--allowedTools` and `--add-dir` are never used. Prompts are denied (`--permission-prompts
  none`) until KalCode can answer them (Z4). Details in `docs/PROVIDERS.md` §5.
- **Business rule**: bring your own provider — the user's own CLI sign-in, subscription or key;
  KalCode never pays for or proxies inference and holds no provider credentials.
- **IPC**: `providers_list` (cached) and `providers_detect` (off the main thread, records
  events; works even if the core failed to start, then events are skipped).
- **UI**: Providers surface is Available; Dashboard runtime health has a Providers row.

## Open items

- The `interrupt` control request's inner field (`subtype`) is inferred from the documented
  envelope; guarded by the capability check and the 5 s fallback. Verify with the owner's
  approval in a real session (Z3).
- `codex login status` wording and exit codes are undocumented; unknown output → `unknown`.
- Gemini CLI is not installed here; its detection is tested only with the fake executable.
- Host approvals (`--permission-prompt-tool` / SDK host, Codex app-server approvals) arrive with
  the permission engine (Z4); mappings then become exact where possible.
- `docs/CONTRACTS.md` lists the provider commands as returning `ProviderDetection[]`; they return
  `ProviderStatus[]` (which wraps `ProviderDetection` with capabilities) — lead to reconcile.
- No migration was needed (`0003` unused).
