## 2. What it looks like

- **Rail** — a column between the sidebar and the page: WORKSPACES header (count, + menu: New
  workspace…, Open folder…, Add repository…, New rail folder…; hide), a sunken search field, then
  PINNED / FOLDERS / RECENT / ARCHIVED. A workspace row: caret, initials tile, name (strike-through +
  "Missing" when the folder is gone), badges **! n** (needs you, neutral emphasized — amber stays
  Paused-only) and **● n** (working, breathing dot), a hover ⋯ menu. Provider rows use the W0
  `ProviderGlyph`; thread rows the display-status glyph in its tone + name + age. The active
  workspace is the rail's one lit item. Under 1400 px (e.g. 1366×768) it starts as a 48 px strip
  of tiles (dot badges); expanding it there lasts for the session; Ctrl+Shift+B toggles it.
- **Home** — DISPLAY-role greeting, a date eyebrow, one plain summary sentence, actions (New
  thread, Open folder, Search). Then Needs you / Running now / Finished since your last visit (one
  "All clear" panel when all three are empty), Recent workspaces (cards with Continue), Pick up
  where you left off, Recent work (Today / Yesterday / This week). One column → two → three by
  container width. First run: "Welcome to KalCode." with three numbered steps and an honest preview
  of what will appear.
- **Project** — eyebrow PROJECT, the workspace name, path + branch chip (↑↓), actions (New thread,
  Open in Code, Pin, Show in File Explorer), KPI row, then Files | Git status + Recent files |
  Threads, Terminals, Branches, "Also in this workspace", Search opt-in.
- **Palette** — typing searches the locator: kind filter pills, understood filters as chips
  ("Yesterday", "Codex", "Needs you"), "Also matching …" aliases, results with highlighted matches,
  kind, subtitle and status in words; Enter opens the best match unless the text names a command.

## 4. Migration v11 — isolated, not registered

`kalcode_locator::RAIL_LOCATOR_MIGRATION` (`version: 11`, `name: "rail_locator"`,
`crates/locator/src/lib.rs`), SQL in `crates/locator/migrations/0011_rail_locator.sql`
(numbered v11 after main registered v7 git, v8 context, v9 workspace_ui and v10 notifications):

```sql
CREATE TABLE workspace_groups (
  id TEXT PRIMARY KEY NOT NULL, name TEXT NOT NULL CHECK (length(name) BETWEEN 1 AND 80),
  position INTEGER NOT NULL, collapsed INTEGER NOT NULL DEFAULT 0 CHECK (collapsed IN (0, 1)),
  created_at TEXT NOT NULL) STRICT;
CREATE TABLE workspace_rail (
  workspace_id TEXT PRIMARY KEY NOT NULL,            -- a Z1 workspace id (no FK: Z1 owns it)
  name TEXT CHECK (name IS NULL OR length(name) BETWEEN 1 AND 80),   -- rail name; NULL = folder
  group_id TEXT REFERENCES workspace_groups (id) ON DELETE SET NULL,
  pinned_at TEXT, archived_at TEXT, position INTEGER,
  collapsed INTEGER NOT NULL DEFAULT 0 CHECK (collapsed IN (0, 1)),
  index_messages INTEGER NOT NULL DEFAULT 0 CHECK (index_messages IN (0, 1)),
  updated_at TEXT NOT NULL) STRICT;
CREATE INDEX workspace_rail_pinned_idx ON workspace_rail (pinned_at) WHERE pinned_at IS NOT NULL;
CREATE INDEX workspace_rail_group_idx  ON workspace_rail (group_id)  WHERE group_id IS NOT NULL;
CREATE TABLE locator_entries (
  id INTEGER PRIMARY KEY,
  entity_kind TEXT NOT NULL CHECK (entity_kind IN ('thread','workspace','remote_workspace',
    'terminal','provider','agent','mission','task','worktree','automation','file','command','activity')),
  entity_id TEXT NOT NULL, workspace_id TEXT, provider_id TEXT,
  title TEXT NOT NULL, subtitle TEXT, status TEXT, updated_at TEXT NOT NULL,
  has_body INTEGER NOT NULL DEFAULT 0 CHECK (has_body IN (0, 1)),
  UNIQUE (entity_kind, entity_id)) STRICT;
CREATE INDEX locator_entries_recency_idx   ON locator_entries (updated_at DESC);
CREATE INDEX locator_entries_workspace_idx ON locator_entries (workspace_id) WHERE workspace_id IS NOT NULL;
CREATE VIRTUAL TABLE locator_fts USING fts5(title, subtitle, body,
  content = '', contentless_delete = 1, tokenize = 'trigram remove_diacritics 1');
```

Differences from the sketch in `CONTRACTS_ADVANCED.md` §9: `workspace_rail.name` (rename in the
rail without touching Z1's `workspaces`), `workspace_rail.index_messages` (the per-workspace
message-search opt-in, decision 6), `locator_entries.has_body`, `id` instead of `rowid`,
`contentless_delete = 1` and `remove_diacritics 1`. No foreign key to another campaign's table.

**Registration (lead, after v10):** append `kalcode_locator::RAIL_LOCATOR_MIGRATION` to
`kalcode_core::db::MIGRATIONS` (native-core would then depend on `kalcode-locator`, which depends
on native-core — so either move the SQL into `crates/native-core/migrations/0011_rail_locator.sql`
with the same bytes and a `RAIL_LOCATOR_MIGRATION` constant there, as was done for v10
`NOTIFICATIONS_MIGRATION`, re-exported from `kalcode_locator`, or register it where the app
assembles its migration list). Its test, `locator::migration_is_isolated_and_well_formed`, asserts
v11 is *not* registered on this branch; flip that assertion at integration. `Store::open` switches
from the session-only in-memory store to the database automatically once the tables exist;
`open_core`'s E2E-only provisional path turns itself off once `MIGRATIONS` contains v11.

**Before v11 is registered** (this branch): rail changes and the index live in a private in-memory
SQLite database for the session (`Store::Memory`; the rail shows "Rail changes last for this session
in this build"). Nothing is written to the user's database under an unknown schema (tested:
`locator::without_v11_everything_works_for_the_session`). The **E2E** binary applies the provisional
list (registered v1–v10, then v11; stand-ins would fill any gap) only with
`KALCODE_E2E_PROVISIONAL_SCHEMA=v11` **and** an explicit `KALCODE_DATA_DIR`
(`locator_commands::open_core`, `#[cfg(feature = "e2e")]`).
