# Campaign Z1 — Workspace + Terminal

Goal: a real project can be opened in KalCode and used through a real terminal, and both survive
a restart.

## Design

- **Workspace**: a project folder the user chose through the native folder picker. Stored with its
  canonical path; reopening the same folder reuses the same workspace. One workspace is active at
  a time; the choice persists. Removing a workspace only removes it from KalCode's list — files are
  never touched.
- **Terminal**: a native pseudo-terminal (ConPTY on Windows, openpty on macOS/Linux) running one
  of the shells KalCode detected, started in the workspace folder. The WebView never supplies an
  executable path or a working directory; it picks a detected shell by id.
- **Streaming**: output bytes flow over a per-terminal Tauri channel. Native keeps a bounded
  scrollback per terminal, so a view that re-attaches (tab switch, navigation, reload) replays it.
  Output is not stored in the database or the event log.
- **Lifecycle events**: `workspace.created`, `workspace.opened`, `workspace.removed`,
  `shell.started`, `shell.completed` (exit 0), `shell.failed` (non-zero or killed).
- **Restart**: processes cannot survive KalCode exiting. On the next launch the workspace's
  terminal tabs come back marked as ended, each with a Restart action that starts a fresh shell
  in the same tab.
