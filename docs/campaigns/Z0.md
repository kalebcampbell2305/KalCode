## Completion report

```text
CAMPAIGN   Z0 — Foundation
STATUS     PASS with one open item: CI is written but has not executed (no GitHub remote yet)
```

**Implemented.** Rust native core (SQLite with checksummed, backed-up migrations; event protocol
v1 store/bus; typed atomic settings; flags; diagnostics; redacting JSON logs; error taxonomy;
data-folder lock; interrupted-session detection) · OS credential store crate · Tauri 2 shell
(allow-listed IPC, strict CSP, environment hardening, startup-error path, single instance) ·
React desktop UI (Dashboard, Settings, JARVIS and other gated surfaces, command palette, toasts)
· `@kalcode/protocol` (Rust-generated types, plans, provider/permission contracts) ·
`@kalcode/ui` (tokens, primitives, brand masters) · brand pipeline using the owner's artwork ·
kalcoded.com (Astro + Worker + D1) · CI · documentation and ADRs.

**Tests.** Rust 79 (incl. OS keychain) · TypeScript unit 147 (desktop 29, website 112,
protocol 6) · desktop UI 14 (Playwright + axe) · desktop real-app E2E 2 · website E2E 62.

**Runtime QA.** The desktop app ran in dev mode throughout with hot reload; release binaries
and Windows installers (MSI 4.1 MB, NSIS 3.1 MB) built; the real app was driven end to end
(settings, credential store, graceful quit, relaunch, forced kill, newer-schema refusal); the
website ran on the real Worker with local D1, and the form was exercised.

**Visual QA.** All surfaces reviewed at 1440/1280/1024 in light and dark; website at 1440/390.
Fixed: faint-text contrast, artwork seams, page alignment, truncated labels, wrapping rows.

**Accessibility.** axe (WCAG 2.2 AA) clean on every desktop surface and website page in both
themes; keyboard paths tested; reduced motion honoured; status never colour-only.

**Security.** Independent review found no critical/high issues. Fixed: log-redaction bypasses,
WebView2 DevTools environment override in release, data-dir override in release, subscription
leaks, non-atomic settings events, backup edge cases, IPv6 rate-limit evasion, `//` redirect
risk, GET form fallback. Actions pinned to SHAs; capability ACL checked in CI.

**Known issues.**
- CI has never executed (no GitHub remote configured).
- Early-access consent is unverified until the first email, which will be a confirmation
  request (documented on the privacy page). Turnstile would need a Cloudflare widget the
  current credentials cannot create.
- The early-access honeypot E2E check failed once in a full run and passed in every rerun
  (27/27 across three repeats); treated as flaky, to be stabilised.
- Cloudflare Web Analytics is enabled for the zone; the site blocks its injection with
  `no-transform` (verified live). Disabling it in the dashboard would remove the dependency.
- Installers and updates are unsigned (planned: Z13).
- macOS and Linux builds are configured in CI but untested on real machines.
- Website mobile Lighthouse performance 91–94 (one render-blocking stylesheet; inlining it would
  weaken the CSP).
- Release builds do not remap source paths in panic locations.

**Deferred.** Provider detection and connections (Z2), workspaces/terminal (Z1), threads (Z3),
permissions engine (Z4), accounts/billing/updater (Z13).

**Next campaign.** Z1 — Workspace + Terminal: create/open/persist workspaces, native PTY with
xterm.js, terminal tabs and events, workspace restoration, path containment checks.
